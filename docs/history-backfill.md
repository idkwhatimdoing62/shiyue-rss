# 自动历史回补

在订阅设置中选择「开始历史回补」。所有订阅使用相同的自动检测流程，无需选择网站或填写归档地址。

1. 读取订阅源，通过源声明的网页链接定位发布者网站。没有网页链接时，尝试文章所在网站首页。
2. 从网页中发现「归档」「按日期」「Archives」「所有文章」等入口。只检查同站候选页面，不猜测固定归档路径。
3. 验证候选页是否包含文章链接、标题结构或年份月份导航。日期索引可以继续定位到文章列表。导航、侧栏、分类和标签链接不作为文章导入。
4. 找到可验证的归档页时优先使用它；没有找到或候选页不可访问时，使用 RSS/Atom 的 `prev-archive` 或 `next` 链接。
5. 订阅设置显示检测结果及实际使用的来源。既没有可验证归档页、又没有源分页链接时，明确提示只能读取当前条目。

回补每批最多处理 50 个文章条目，历史文章默认已读。RSS/Atom 条目保留源中的发布日期、作者、正文及 ID；归档网页文章按原网页提取正文。已保存的文章继续受资料库去重规则约束。

检测最多检查 6 个候选归档页面。每批最多读取 10 个历史列表页，发现不足 50 条时也可以结束本批，下一批继续读取。重复分页地址会停止继续访问；分页失败保留原地址，可选择「重试当前分页」。

自动检测不保证找到每个网站的全部历史：需要登录、仅由 JavaScript 渲染的归档、无法验证的页面结构、反爬或网络拦截都会限制结果。它不会绕过这些限制，也不会将读完已发现的页面称为「完整抓取所有历史」。回补进度仍属于本次运行，退出软件不会保存未完成的分页队列。

RSS/Atom 分页关系依据 [RFC 5005](https://www.rfc-editor.org/rfc/rfc5005)。同一分页链中的内容可能随站点更新而变化，不能据此保证历史完整性。

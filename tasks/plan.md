# Implementation Plan: 历史回补与文章全文抓取

## Overview

为 RSS 阅读器增加两条后台工作流：对阮一峰博客从归档页按 50 篇一批进行历史回补，并支持分页加载、进度、暂停、继续和失败重试；对支持的文章提供按需访问原文、提取正文并缓存到已有文章记录的功能。正常 Atom/RSS 刷新流程保持不变。

## Architecture Decisions

- 历史回补使用独立的会话工作流，不改变 RSS 刷新的单次 Atom 语义；阮一峰归档页按月份解析，按文章 URL 去重。
- 回补任务使用固定批量大小 50，UI 的“加载下一批”同时推进任务；新插入的历史文章默认 `is_read=1`，已有文章的阅读状态不覆盖。
- 全文抓取复用已有公开 URL 校验和正文提取器，在后台线程执行，成功后只更新文章 `content`，失败保留原 RSS 内容并可重试。
- 所有网络请求离开 egui 帧；数据库写入使用现有维护代际围栏，避免维护/恢复期间写入旧连接。
- GitHub CLI 当前无法读取本机配置（权限错误），因此先用本仓库 `tasks/` 记录任务；完成后再按仓库发布流程提交代码。

## Dependency Graph

1. 数据库写入/更新接口与回补状态类型
2. 阮一峰归档解析与分页批量抓取
3. 全文抓取与正文提取工作流
4. GUI 控制、进度和错误重试
5. 测试、构建和打包验证

## Task List

### Phase 1: Foundation

- [ ] Task 1: 增加历史回补和全文更新所需的数据库接口。
- [ ] Task 2: 增加阮一峰归档页解析、URL 去重和 50 条分页游标。

### Checkpoint: Foundation

- [ ] 解析器单元测试覆盖分页、相对链接和重复 URL。
- [ ] 数据库测试验证历史文章默认已读、全文更新不覆盖用户状态。

### Phase 2: Core Features

- [ ] Task 3: 实现历史回补后台工作流，支持启动、暂停、继续、重试和进度快照。
- [ ] Task 4: 实现按需全文抓取后台工作流，复用正文提取器并缓存成功结果。

### Checkpoint: Core Features

- [ ] 两条工作流均不在 UI 线程执行网络请求。
- [ ] 失败后仍可查看原内容并再次发起任务。

### Phase 3: UI and Validation

- [ ] Task 5: 在订阅设置/文章工具栏接入操作按钮、进度、分页和状态提示。
- [ ] Task 6: 完成测试、构建和 Windows release 产物验证。

### Checkpoint: Complete

- [ ] 新订阅仍只走 Atom/RSS 刷新。
- [ ] 阮一峰回补每批最多 50 篇，切换到下一批时才继续抓取。
- [ ] 全文抓取成功后文章正文更新，失败可重试且不丢 RSS 摘要。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| 归档页面结构变化 | 高 | 使用稳定的文章链接/标题选择器，解析失败显示可重试错误并保留游标 |
| 站点限流或反爬 | 中 | 单批 50 条、串行请求、复用请求重试和公开 URL 校验 |
| 全文页面需要登录/会员权限 | 中 | 提取失败不覆盖已有摘要，UI 明示原因并允许重试 |
| 维护流程与后台写入竞争 | 高 | 通过代际围栏提交，维护期间暂停任务并在 UI 中显示状态 |

## Open Questions

- 当前请求将“翻页时再抓取 50 篇”解释为历史回补归档列表的批量分页；普通 RSS 文章列表继续沿用现有投影和虚拟滚动。
